# System Design

対象にAWS CDKまたはCloudFormationが含まれる場合は、[AWS CDK / CloudFormation Design](../aws-cdk-cloudformation-design/SKILL.md)を最後まで読み、必要な参照資料を適用する。

規約の正本を分ける。CloudWatch Logs保持日数はこのスキルが管理し、CDK / CloudFormationの設定境界、固定セキュリティ基準、命名、更新・削除安全性は`aws-cdk-cloudformation-design`が管理する。同じ規約を両方へ複製しない。

設計・実装・レビューの対象にAWSへのデプロイが含まれる場合、CloudWatch Logsを作成するすべてのリソースについて保持期間を確認する。AWS以外ではこの規約を適用しない。

- 新しく作成するロググループは、IaCで保持期間を明示的に180日に設定する。AWSの無期限保持へ依存しない。
- Lambdaなどが暗黙に作成するロググループも対象に含め、使用するIaCの合成結果または同等の出力で設定を確認する。
- 法令、監査、障害調査、環境特性などにより180日以外が必要な場合は推測で変更せず、理由と候補期間を示してユーザーへ確認する。
- 既存ロググループへの保持期間設定は古いログを期限切れにするため、新規設計の依頼だけを根拠に変更しない。対象と影響を示してユーザーへ確認する。
- デプロイが依頼範囲に含まれる場合は、デプロイ後に実際のロググループの保持期間が180日またはユーザー指定値であることを確認する。

## AWSフロントエンドでのAmplify採用判断

AWS上のWebフロントエンドを設計するときは、「Amplify」を一括りにせず、次を分けて採否を判断する。

- Amplify Hosting
- Amplify Backend / Gen 2
- `aws-amplify`などのフロントエンドライブラリ

静的SPAを作り込み、CDKやCloudFormationでインフラを管理し、配信・キャッシュ・オリジン・WAF・認証先への経路を明示的に制御する場合は、S3とCloudFrontを第一候補にする。Amplify Hostingは、ブランチ連携、プレビュー環境、ビルド・デプロイの一体運用といった管理機能に価値がある場合に採用する。単に静的ファイルを配信するためだけには追加しない。

Amplify Hostingを採用しない判断から、フロントエンドライブラリまで自動的に排除しない。CognitoのSRP、トークン更新、認証状態管理などを安全に実装するために`aws-amplify/auth`だけを使う構成は独立に評価する。反対に「Amplify不採用」が製品・依存ライブラリを含む要件なら、ライブラリも含めて除外し、代替手段と自前実装範囲を明示する。

設計書では少なくとも、Hosting、Backend、フロントエンドライブラリの採否を個別に記載し、「Amplifyを使う／使わない」だけで済ませない。

このスキルに別の設計規約を推測で追加しない。

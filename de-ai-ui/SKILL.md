# UIの脱AI臭

UIの文言と情報構造を、実際の利用目的に必要な要素だけで構成する。

## 判断原則

- 小さな英語ラベル、主見出し、説明文を機械的に3段重ねにしない。画面の目的が見出しだけで明確なら、見出しだけを表示する。
- 日本語UIに装飾目的の英語を混ぜない。英語は固有名詞、規格名、ユーザーが識別に必要な値に限る。
- 説明文は、操作結果、制約、危険性など、ユーザーの判断に必要な情報がある場合だけ表示する。
- 開発時の意思決定、内部仕様、実装上の都合を、そのまま利用者向けの説明文として画面に残さない。表示形式など利用者が見れば分かる挙動は説明せず、操作判断に必要な結果や制約だけを示す。
- どの画面にも同じヒーロー、カード、バッジ、グラデーション、過剰な角丸や余白を当てはめない。既存製品の情報密度とコンポーネント体系を優先する。
- 見た目を簡素化しても、現在の対象、保存範囲、破壊的操作など誤操作防止に必要な情報は削らない。必要なら操作箇所の近くへ短く配置する。
- 既存UIを修正するときは、周辺画面との一貫性を保ち、今回の箇所だけ別のデザイン言語にしない。

## 実装時の確認

1. 各ラベルについて、ユーザーの判断または操作に必要か確認する。
2. 同じ意味を見出しと説明で繰り返している場合は一つにまとめる。
3. 英語の眉見出しが装飾だけなら削除する。
4. 説明を削除した結果、対象範囲や操作結果が曖昧になる場合は、入力ラベルや操作ボタン側で明確にする。
5. 仕様決定の理由、実装方式、データ形式など、開発者向けの情報が画面文言に混入していないか確認する。
6. 実画面で情報密度、余白、周辺コンポーネントとの統一感を確認する。
